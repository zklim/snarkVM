# Recovery branch publication

The commit containing this note publishes the recovery implementation and retained
evidence after the upstream mainnet rebase. `quantum-recoverability-aerie` inherits
the committed `quantum-recoverability-pqs` core and adds its separate adapter.

`MAINNET_COMPARISON.*`, `UPSTREAM_REBASE.md` and the original fields in
`RECOVERY_SOURCE_MANIFEST.json` describe the validated snapshot captured before
publication. Their earlier HEADs, dirty-overlay status and “uncommitted/not pushed”
wording identify that capture point. They do not identify the current published tip.
Use the Git commit containing this note for the published source revision. The
manifest's `publication` section records exact sibling/core revisions where needed.

The Rust/Cargo files and dependency locks retain the validated contents. Publication
adds this note, a sanitized [validation summary](RECOVERY_VALIDATION.json), metadata
qualifications and a Python-cache ignore rule. Generated bytecode and signing-key
files are excluded. The earlier source archives remain the test capture identities.

Clone matching branches of `zklim/snarkVM` and `zklim/snarkOS` into sibling directories
named `snarkVM` and `snarkOS` for the core, or `snarkVM-aerie` and `snarkOS-aerie` for
the adapter. In snarkOS, check out the exact VM commit recorded under
`publication.vm_dependency` in `RECOVERY_SOURCE_MANIFEST.json` before building.
The local Cargo paths deliberately select that matching sibling source tree.

Both public activation heights remain unscheduled. This publication does not deploy
a network or extend the cryptographic guarantees and test coverage stated in the reports.
